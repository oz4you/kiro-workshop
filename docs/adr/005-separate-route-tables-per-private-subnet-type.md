# ADR-005: プライベートサブネット用途別にルートテーブルを分離する

## ステータス

Accepted

## コンテキスト

プライベートサブネットが2種類（private-ecs-task, private-data）あり、どちらも現時点ではインターネットへのルートなし（ローカルのみ + S3 Gateway エンドポイント）。ルートテーブルを共有するか用途別に分離するかの判断が必要になった。

## 決定

private-ecs-task 用と private-data 用で2つのルートテーブルを作成する。

## 代替案

**全プライベートサブネットで1つのルートテーブルを共有する**

却下理由:
- 後続 Step で ECS タスク用サブネットにだけルートを追加する可能性がある（追加の VPC エンドポイント等）
- 共有している場合、一方だけにルートを追加できず設計変更が必要になる
- ルートテーブルは無料リソースなのでコスト影響なし

## 検証

| ツール | 確認内容 | 結果 |
|--------|----------|------|
| AWS Documentation MCP `search_documentation` | サブネット用途別ルートテーブル分離のパターン | ✅ SAP on AWS、Neptune 事例で用途別 RT パターンを確認 |
| Terraform MCP `get_provider_details` | `aws_vpc_endpoint` の `route_table_ids` がリスト型 | ✅ 確認済み。S3 Gateway EP を両方の RT に関連付け可能 |
| コスト | ルートテーブルの課金 | ✅ 無料。追加コストなし |

## 帰結

- S3 Gateway エンドポイントは両方のルートテーブルに関連付ける必要がある
- 将来のルート追加は対象の RT にのみ行えばよく、影響範囲が限定される
- **再検討トリガー**: プライベートサブネットの種類がさらに増え、RT 管理が煩雑になった場合
